# Lesson Builder — สร้างบทเรียนที่ทำให้เข้าใจจริง

บทเรียนที่ดีไม่ใช่การเทความรู้ แต่คือการพาผู้เรียนจาก "ไม่รู้" → "เข้าใจ" → "ใช้เป็น" ทีละขั้น โดยมีจังหวะให้คิด ลองทำ และได้ feedback ทันที skill นี้ใช้หลัก **Bloom's Taxonomy** (กำหนดว่าแต่ละกิจกรรมฝึกการคิดระดับไหน) และ **Gagné's 9 Events** (ลำดับการสอนที่ได้ผล: ดึงความสนใจ → บอกเป้าหมาย → เชื่อมความรู้เดิม → นำเสนอ → ชี้แนะ → ให้ลองทำ → feedback → ประเมิน → ย้ำ/ถ่ายโยง)

## ขั้นที่ 1 — หาองค์ความรู้

1. มองหา `study/<slug>/knowledge.md` ในไดเรกทอรีทำงาน ถ้ามี ใช้เป็นแหล่งหลัก (นี่คือผลจาก deep-study)
2. ถ้าไม่มี แต่ผู้ใช้แนบเอกสารหรือเนื้อหายาวมา ให้ทำตาม skill **deep-study** ก่อน (ถ้ามี skill นี้) เพราะการสอนสิ่งที่ตัวเองยังย่อยไม่ครบจะได้บทเรียนตื้น ๆ
3. ถ้าเป็นหัวข้อทั่วไปสั้น ๆ ที่ไม่มีเอกสาร ทำบทเรียนจากความรู้ได้เลย แต่ตรวจข้อเท็จจริงสำคัญด้วยการค้นเว็บถ้าทำได้

## ขั้นที่ 2 — วางโครงหลักสูตร

- แบ่งเป็น **บท (module)** ตาม "ลำดับการเรียนรู้" ใน knowledge.md — 1 บท ≈ 1 แนวคิดหลัก หรือกลุ่มแนวคิดที่เรียนจบได้ใน 15–25 นาที
- เนื้อหาสั้น (1–3 แนวคิด) ทำเป็นไฟล์เดียว เนื้อหายาวให้ทำไฟล์ภาพรวม `index.html` + หนึ่งไฟล์ต่อบท เพื่อให้เรียนเป็นช่วง ๆ ได้
- ตั้ง **จุดประสงค์การเรียนรู้** ต่อบทด้วยคำกริยาที่วัดได้ ("อธิบายได้ว่า...", "แยกแยะ...กับ...ได้", "นำ...ไปใช้กับ...ได้") ไม่ใช่ "รู้เรื่อง..."

## ขั้นที่ 3 — เขียนแต่ละบท

แต่ละบทใช้โครงนี้ (ปรับตามธรรมชาติเนื้อหาได้):

1. **เปิดเรื่องด้วยสถานการณ์/คำถามชวนคิด** — ปัญหาจริงที่ผู้เรียนจะแก้ได้เมื่อเรียนจบบท ดึงความสนใจและให้เหตุผลว่าทำไมต้องเรียน
2. **จุดประสงค์** 2–4 ข้อ
3. **เชื่อมความรู้เดิม** — "จำได้ไหมว่าบทที่แล้ว..." หรือเชื่อมกับประสบการณ์ในชีวิต
4. **เนื้อหา** — อธิบายเป็นขั้น ภาษาเป็นกันเอง ประโยคสั้น ทีละแนวคิด ใช้อุปมาเปรียบเทียบ ใส่ศัพท์อังกฤษในวงเล็บครั้งแรกที่เจอ
5. **แผนภาพ** — อย่างน้อย 1 ภาพต่อบท เลือกชนิดให้ตรงกับสิ่งที่ต้องการสื่อ (ดู `references/activity-guide.md`) ใช้ Mermaid เป็นหลัก หรือ SVG/ตาราง HTML เมื่อ Mermaid ไม่เหมาะ แผนภาพต้องอธิบายกลไกจริง ไม่ใช่กล่องสวย ๆ ที่ไม่สื่ออะไร
6. **ตัวอย่างแบบแสดงวิธีทำ (worked example)** — ทำให้ดูทีละขั้นพร้อมเหตุผลของแต่ละขั้น
7. **กล่อง "ระวังเข้าใจผิด"** จากส่วนความเข้าใจผิดใน knowledge.md
8. **ลองคิด (check for understanding)** — คำถามสั้น 1–2 ข้อกลางบท กดดูคำตอบได้
9. **แบบฝึกหัด** — ไล่ความยากจากง่ายไปยาก ครอบคลุมระดับ Bloom ที่เหมาะกับเนื้อหา (ดูการเลือกชนิดใน `references/activity-guide.md`) ทุกข้อมีเฉลย **พร้อมเหตุผล** ซ่อนไว้ให้กดดู
10. **สรุปท้ายบท** 3–6 ข้อ + "คำถามพาไปบทถัดไป"

ปิดท้ายทั้งหลักสูตรด้วย **แบบทดสอบรวม** (10–20 ข้อ ตามขนาดเนื้อหา) ผสมทุกบท มีการตรวจคะแนนอัตโนมัติ และแต่ละข้อบอกว่าถ้าผิดควรกลับไปทบทวนบทไหน และ **กิจกรรมประยุกต์/สร้างสรรค์** 1 ชิ้น (โจทย์ปลายเปิดที่ผู้ใช้ส่งคำตอบกลับมาให้ Claude ตรวจได้)

### หลักการเขียนที่ทำให้บทเรียนได้ผล
- **ตัวลวงในข้อปรนัยต้องมาจากความเข้าใจผิดจริง** ไม่ใช่ตัวเลือกมั่ว ๆ — เพราะเฉลยของตัวลวงคือจังหวะที่ผู้เรียนได้แก้ความเข้าใจผิด
- **feedback อธิบายว่าทำไม** ทั้งข้อถูกและข้อผิด
- **สถานการณ์ตัวอย่างหลากหลายบริบท** (งาน ชีวิตประจำวัน ข่าว) เพื่อให้ถ่ายโยงความรู้ได้ ไม่ติดอยู่กับตัวอย่างเดียว
- อย่าใส่ทุกอย่างจาก knowledge.md — เลือกสิ่งที่ช่วยให้บรรลุจุดประสงค์

## ขั้นที่ 4 — สร้างไฟล์

ใช้ `assets/lesson-template.html` เป็นฐาน (อ่านคอมเมนต์ในไฟล์ — มี CSS, โหมดมืด, Mermaid, และ JavaScript สำหรับปุ่มเฉลยและแบบทดสอบตรวจคะแนนแล้ว) คัดลอกไปที่ `study/<slug>/lesson/` แล้วเติมเนื้อหาตามรูปแบบ component ที่ template กำหนด ไม่ต้องเขียน CSS/JS ใหม่

ตรวจก่อนส่ง:
- เปิดไฟล์ด้วยเบราว์เซอร์ (เช่น Playwright ถ้ามี) ดูว่า Mermaid render ได้ ไม่มี error ใน console และปุ่มเฉลย/ตรวจคะแนนทำงาน
- ทุกแบบฝึกหัดมีเฉลยและเหตุผล ทุกข้อในแบบทดสอบมี `data-answer` ถูกต้อง

ถ้าสภาพแวดล้อมมีเครื่องมือเผยแพร่หน้าเว็บ (เช่น Artifact) ให้เสนอเผยแพร่บทเรียนเป็นลิงก์เพื่อเปิดในมือถือได้ ถ้าผู้ใช้ขอเป็น PDF/Word ให้ใช้ skill ที่เกี่ยวข้องแปลงต่อ

## ส่งงาน

บอกผู้ใช้: โครงบทเรียน (ชื่อบท + เวลาโดยประมาณ), วิธีเรียนที่แนะนำ (อ่าน → ลองคิด → แบบฝึกหัด → แบบทดสอบ), ที่อยู่ไฟล์ และเสนอ: "อยากได้ไฟล์เสียงครูสอนบทนี้ (audio-teacher) ไว้ฟังระหว่างทำอย่างอื่นไหม" และ "ส่งคำตอบกิจกรรมสร้างสรรค์มาให้ตรวจได้เลย"

เมื่อผู้ใช้ส่งคำตอบมาให้ตรวจ ให้ตอบแบบครู: ชมสิ่งที่ถูกอย่างเจาะจง ชี้จุดที่คลาดเคลื่อนพร้อมเหตุผล แล้วให้คำถามต่อยอด 1 ข้อ
