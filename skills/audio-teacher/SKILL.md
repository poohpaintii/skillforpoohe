# Audio Teacher — ครูสอนผ่านเสียง

ผู้ฟังกำลังทำอย่างอื่นอยู่ (ขับรถ ทำอาหาร เดิน) จึง **มองไม่เห็นจอ ย้อนอ่านไม่ได้ และสมาธิแบ่งไปบางส่วน** ทุกการตัดสินใจในการเขียนสคริปต์ต้องคิดจากข้อจำกัดนี้ — นี่คือเหตุผลที่สคริปต์เสียงต้องต่างจากบทเรียนที่เป็นตัวอักษร ไม่ใช่แค่นำบทเรียนมาอ่านออกเสียง

## ขั้นที่ 1 — หาเนื้อหาต้นทาง

ลำดับความสำคัญ: `study/<slug>/knowledge.md` (จาก deep-study) → ไฟล์บทเรียนใน `study/<slug>/lesson/` (จาก lesson-builder) → เอกสารที่ผู้ใช้แนบ (ถ้าเนื้อหายาว ทำ deep-study ก่อน) ถ้าผู้ใช้บอกเวลาที่มี (เช่น "ขับรถ 20 นาที") ให้ใช้กำหนดความยาวตอน

## ขั้นที่ 2 — แบ่งตอน

- 1 ตอน ≈ 8–15 นาที (≈ 1,200–2,200 คำไทย ที่ความเร็วพูดสอนประมาณ 150 คำ/นาที) ช่วงสั้นช่วยให้ฟังจบในเวลาว่างและหยุดพักได้
- 1 ตอนควรสอน 1 แนวคิดหลักให้จบ ตามลำดับการเรียนรู้ใน knowledge.md
- ถ้าเนื้อหายาวมาก เสนอแผนตอนให้ผู้ใช้เห็นก่อน (ชื่อตอน + ความยาว) แล้วทำต่อได้เลย ไม่ต้องรอถ้าผู้ใช้ขอให้ทำทั้งหมด

## ขั้นที่ 3 — เขียนสคริปต์การสอน

บันทึกเป็น `study/<slug>/audio/ep01-<ชื่อสั้น>.txt` ตามรูปแบบใน `references/script-guide.md` (อ่านไฟล์นั้นก่อนเขียน — มีโครงตอน ตัวอย่างสำนวน และกฎการเขียนสำหรับ TTS)

หลักสำคัญโดยสรุป:
- **พูดเหมือนครูที่ใจดีและเข้าใจเรื่องจริง** คุยกับผู้ฟังคนเดียว ใช้ "เรา" "คุณ" ใช้คำลงท้าย (ครับ/ค่ะ ให้ตรงกับเพศเสียงที่เลือก) แต่อย่าใส่ทุกประโยค
- **บอกทาง (signposting)** — บอกก่อนว่าจะพูดอะไร พูด แล้วสรุปว่าพูดอะไรไป เพราะผู้ฟังย้อนดูหัวข้อไม่ได้
- **ทวนซ้ำแนวคิดหลัก** อย่างน้อย 3 ครั้งในรูปแบบต่างกัน (นิยาม → ตัวอย่าง → สรุป)
- **อธิบายเพิ่มเติมและยกตัวอย่างมากกว่าบทเรียนตัวอักษร** — ตัวอย่างใกล้ตัว เล่าเป็นเรื่องสั้น อุปมาที่เห็นภาพ
- **แปลงแผนภาพเป็นคำพูด** — "ลองนึกภาพกล่องสามกล่องเรียงจากซ้ายไปขวา..." ห้ามพูดว่า "ดูจากภาพ"
- **ชวนคิดแล้วเว้นจังหวะ** — ตั้งคำถาม ใส่ `[pause 3]` ให้ผู้ฟังคิด แล้วเฉลยพร้อมเหตุผล
- **ไม่มีสิ่งที่ฟังแล้วงง**: ตาราง สัญลักษณ์ สูตรยาว ตัวย่อ URL วงเล็บซ้อน — เขียนเป็นคำพูดทั้งหมด (ดูกฎ TTS ใน script-guide)
- ตรวจความถูกต้องกับ knowledge.md อย่าแต่งข้อเท็จจริงเพิ่มเพื่อให้ฟังลื่น

## ขั้นที่ 4 — สร้างไฟล์เสียง

```bash
python <skill-dir>/scripts/make_audio.py study/<slug>/audio/ep01-xxx.txt study/<slug>/audio/ep01-xxx.mp3 \
    --voice th-TH-PremwadeeNeural --rate -5%
```

- เสียงไทย: `th-TH-PremwadeeNeural` (ผู้หญิง, ค่าเริ่มต้น → ใช้ "ค่ะ") หรือ `th-TH-NiwatNeural` (ผู้ชาย → ใช้ "ครับ") ถามผู้ใช้เฉพาะถ้าเขาเคยบอกความชอบไว้หรือดูสำคัญ ไม่งั้นใช้ค่าเริ่มต้น
- `--rate` ปรับความเร็ว (`-10%` ช้าลงสำหรับเนื้อหายาก, `+10%` เร็วขึ้นสำหรับทบทวน)
- สคริปต์จะลองเครื่องยนต์เสียงตามลำดับ: **edge-tts** (เสียงธรรมชาติที่สุด ต้องใช้อินเทอร์เน็ต) → **gTTS** → **espeak-ng** (ออฟไลน์ เสียงเหมือนหุ่นยนต์) และพิมพ์บอกว่าใช้ตัวไหน
- ต้องมี `ffmpeg` ถ้าขาดไลบรารี ติดตั้งด้วย `pip install edge-tts gTTS` ก่อน
- **ถ้าได้ engine=espeak ให้แจ้งผู้ใช้ตรง ๆ** ว่าเสียงยังไม่เป็นธรรมชาติเพราะเครือข่ายเข้าบริการเสียงไม่ได้ และบอกวิธีแก้: รันคำสั่งเดียวกันบนเครื่องตัวเองที่มีอินเทอร์เน็ต (ไฟล์ .txt ใช้ได้ทันที) อย่าส่งไฟล์เสียงหุ่นยนต์โดยไม่บอก

## ขั้นที่ 5 — ตรวจและส่งงาน

- ตรวจความยาวไฟล์ที่สคริปต์รายงานว่าสมเหตุสมผลกับจำนวนคำ
- ส่งไฟล์ MP3 ให้ผู้ใช้ด้วยเครื่องมือส่งไฟล์ที่มี (ถ้ามี) พร้อมไฟล์สคริปต์ .txt
- บอก: รายชื่อตอน + ความยาว, ลำดับที่แนะนำให้ฟัง, และ "คำถามชวนคิดหลังฟัง" 2–3 ข้อที่ผู้ใช้ตอบกลับมาให้ตรวจได้ (ช่วยเปลี่ยนการฟังแบบผ่าน ๆ เป็นการเรียนรู้เชิงรุก)
- เสนอทำ "ตอนทบทวนเร็ว" 3–5 นาที สรุปทุกตอน สำหรับฟังก่อนสอบ/ก่อนใช้งานจริง
